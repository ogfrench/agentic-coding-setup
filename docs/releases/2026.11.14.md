# Agentic Workflow 2026.11.14: conflict-aware agents and multi-user correctness

This source/package release includes PR #109.

## Changes

- Coordinate parallel coding agents by shared behavioral contracts, state ownership and invariants, not file overlap alone. Keep one accountable integrator and verify combined behavior.
- Extend Test Strategy with a multi-user correctness reference: atomic claims, optimistic concurrency, retries, reconnects, authorization, offline editing and deterministic competing-user tests.
- Add Claude routing evaluation fixtures covering semantic API conflicts, shared-resource races, low-risk single-owner settings and intentional repeated copy operations versus transport retries.
- Adopt a bounded, long-term maintainer responsibility contract in repository `AGENTS.md` and `CLAUDE.md` through explicit Claude setup synchronization. Preserve local instructions, detect drift and reject unsafe inputs.
- Improve CI candidate artifact labels and align cross-host installation documentation with the 24-skill Claude and 28-skill ChatGPT editions.

## Acceptance boundaries

- Source CI checks package integrity, source privacy, inventory/budgets, Claude strict plugin validation, clean-config installation smoke tests and an isolated empty-repository sync.
- Model-routing improvements versus skill-disabled baselines are **not yet measured**. The evaluation cases are fixtures, not evidence of actual model outcomes.
- No representative live multi-user application, real downstream repository sync, or installed ChatGPT-account plugin has been verified by this change.
- A published GitHub ZIP does not install or update any user's Claude or ChatGPT plugin. Apply downstream syncs explicitly, review each repository's instructions, and validate resulting PRs before merge.
- Run the release workflow only from reviewed `main` at the exact SHA; check GitHub Release assets and both SHA-256 digests after publication. Omit the optional host acceptance URL unless real evidence exists.
