# Agentic Workflow 2026.12.1: maintainer contracts and shared-state correctness

This release candidate includes PR #109 and the preservation and capability-discovery follow-up PR #110. The version is intentionally December-dated; the candidate was prepared in November 2026.

## Changes

- Coordinate parallel coding agents by behavior, state ownership, shared invariants and API contracts, not file overlap alone. Verify the integrated final revision.
- Extend Test Strategy for multi-user correctness: atomic claims, optimistic concurrency, retries, authorization, reconnects, offline edits and deterministic competing-client cases.
- Adopt a bounded engineering maintainer contract in repository `AGENTS.md` and `CLAUDE.md`; preserve project-owned instructions and existing authorization boundaries.
- Require agents to check relevant skills, plugins, MCP tools and project utilities before every task, using the best-fitting capability selectively rather than recreating it.
- Reject ambiguous or unowned maintainer markers before modifying downstream instructions. Keep inline documentation intact and cover preservation, malformed markers, drift and idempotence with regressions.
- Align the shared Claude (24 skills) and ChatGPT (28 skills) source editions and distribution metadata to `2026.12.1`.

## Verified scope and known limits

- Source CI covers Node regressions, source privacy, both plugin package candidates, Claude strict validation and isolated empty-repository application. Record exact final-SHA CI evidence before publishing.
- Claude model-routing comparisons with a skill-disabled baseline have **not** been performed; evaluation fixtures are not evidence of improved agent behavior.
- A real downstream existing-repository sync, representative multi-user application journey and ChatGPT installed-host verification remain **unverified**.
- The direct `apply.mjs` pipeline is not fully transactional across all writes; the supported sync script prepares changes in a temporary checkout.
- A GitHub release publishes downloadable archives and SHA-256 hashes. It does **not** install or update user plugins, synchronize downstream repositories or authorize merging their PRs.
- Release only from a reviewed `main` SHA, preserve immutable tags, and verify both published archives and `SHA256SUMS.txt`. Omit an acceptance URL unless there is real recorded evidence.
